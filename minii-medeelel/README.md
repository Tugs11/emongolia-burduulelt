# Миний мэдээлэл AI: e-Mongolia PoC

Хэрэглэгч e-Mongolia-д нэвтэрсний дараа **Шинжлэх** товч дарна. Extension:

1. Эрүүл мэндийн даатгал, НДШ, нэхэмжлэх, зээл, тээврийн хэрэгсэл, торгууль, оношилгоо, бичиг баримт, хөрөнгийн мэдээллийг ХУР-аас татна.
2. Тэдгээрийг **AI-аар хураангуйлна**. Жишээ нь: «Паспорт 43 хоногийн дараа дуусна», «9-р сарын НДШ төлөгдөөгүй».
3. Хураангуйн доор **асуулт асууж болно**, жишээ нь «Миний цэргийн алба хаасан мэдээлэл хэр байна?». Татсан мэдээлэлд байгаа зүйлд шууд хариулна. Байхгүй мэдээллийн хувьд «татагдаагүй» гэж хэлээд, e-Mongolia-ийн тохирох үйлчилгээг холбоостой нь санал болгоно.

4. **Бичиг баримт бүрдүүлнэ.** Хэрэглэгч chat-д «Солонгос руу жуулчны виз мэдүүлэх бичиг баримт бүрдүүлэх» гэж бичихэд AI шаардлагатай бичиг баримтын жагсаалт гаргана. Жагсаалт нь хоёр хэсэгтэй:
   - **e-Mongolia-оос авах** лавлагаанууд. Гадаад хэлээрх хувилбар байвал түүнийг сонгоно. **Цуглуулах** дарахад бүгдийг цуглуулаад **нэг ZIP багц** болгож татна: `Downloads/Burduulelt/<зорилго>_<огноо>.zip`. Багцад PDF бүр болон `Жагсаалт.txt` (өөрөө бэлдэх зүйлс, зөвлөмж) орно. Энэ нь Бүрдүүлэлт AI-аас шилжүүлсэн `collector.js` дээр ажилладаг.
   - **Өөрөө бэлдэх** зүйлс: паспорт, зураг, банкны хуулга гэх мэт, тус бүрт товч заавартай.
   
   Маягттай лавлагаа (`/apply` хуудсанд «Хүсэлт» алхам) байвал танигдах талбаруудыг автоматаар бөглөөд «Үргэлжлүүлэх» дарна:
   - **«Эхлэх он» / «Дуусах он»:** визийн шаардлагаас AI тооцсон хугацаагаар (`years`, жишээ нь НДШ-д 1 жил → 2025–2026);
   - **«Хаана зориулж»:** зорилгод тохирох хаягаар (`addressee`, жишээ нь «БНСУ-ын Элчин сайдын яаманд»).
   
   Танигдахгүй шаардлагатай талбар байвал бөглөхгүй, «маягтыг өөрөө бөглөнө (бөглөх: …)» гэж зогсоно. Төлбөртэй эсвэл шууд гардаггүй үйлчилгээг автоматаар авахгүй. Ийм үед «Хуудсыг нээх» товч гарна.
   
   Жагсаалтыг AI-ийн мэдлэгээр гаргадаг. Тиймээс «элчин сайдын яамны албан ёсны жагсаалтаас шалгана уу» гэсэн анхааруулгыг үргэлж харуулна.

Хэрэглэгч ямар нэг тохиргоо, API key оруулахгүй. AI-г төслийн сервис ([worker/](worker/)) дуудна.

Сар бүрийн мэдээллийг компьютер дээр хадгалдаг. Дараа сараас эхлэн хураангуйд «өмнөх сараас өөрчлөгдсөн» хэсэг автоматаар нэмэгдэнэ.

## Урсгал

```
e-Mongolia таб (нэвтэрсэн)
  └─ content.js: /api/routes/xyp-ийг хэрэглэгчийн token-оор дуудна (11 эх сурвалж)
side panel (Шинжлэх)
  ├─ lib.js redact(): РД, нэр, хаяг, утас, зураг, паспорт/машины дугаар… хасна
  ├─ сар бүрийн агшинг chrome.storage.local-д хадгална, өмнөх сартай diff()
  ├─ POST /summarize → { headline, alerts[], changes[], ok[] }
  └─ chat: catalog.js асуултад тохирох e-Mongolia үйлчилгээг (нийтийн жагсаалтаас) олно
           POST /chat { question, history, data, summary, services } → { answer, services[], intent, purpose }
           intent=documents → POST /plan { purpose, emongoliaServices } → { title, items[], tips[] }
           → catalog.js matchService() → background.js COLLECT_DOC → collector.js (PDF)
           (AI зөвхөн өгсөн нэрсээс сонгоно, холбоосыг extension үүсгэнэ)
worker/ (Cloudflare): src/ai.js — prompt + JSON schema, Gemini (давуу) эсвэл Claude
```

## Бичиг баримт цуглуулах туршилт (2026-10-08, бодит бүртгэл дээр)

5 зорилгоор туршсан: ипотекийн зээл, ажилд орох, төрийн албаны шалгалт, хүүхдээ сургуульд бүртгүүлэх, тэтгэвэр тогтоолгох. Chat бүгдийг `documents` гэж таньж, жагсаалт гаргасан. Жагсаалтад орсон e-Mongolia-ийн 12 үйлчилгээг нэг бүрчлэн туршсан:

| Үйлчилгээ | Маягт | Үр дүн |
|---|---|---|
| Иргэний үнэмлэхийн лавлагаа | — («Тодруулга» → Шинээр авах) | ✓ PDF |
| НДШ төлөлтийн лавлагаа | Эхлэх он, Дуусах он, Хаана зориулж | ✓ PDF |
| Хаягийн лавлагаа | Хаана зориулж | ✓ PDF |
| Гэрлэсний бүртгэлийн лавлагаа | — | «бүртгэлгүй» → **Гэрлэсний бүртгэлгүй лавлагаа** руу шилжинэ ✓ PDF |
| Үл хөдлөх хөрөнгийн лавлагаа | Ү дугаар (ХУР-аас, эх «у» үсэгтэй нь) | ✓ PDF |
| Эрүүгийн хариуцлага (байсан / байгаа эсэх) | хүн сонгох radio (ганц) | ✓ PDF ×2 |
| Бүрэн дунд боловсролын үнэмлэх | — | ✓ PDF |
| Төрсний бүртгэлийн лавлагаа | Хэнд: Өөртөө / Хүүхдийн (`subject`) | ✓ PDF (өөртөө); хүүхдийнх → «хүүхдийн регистрийн дугаар»* |
| Суралцаж байгаа тодорхойлолт | — | «бүртгэлгүй» (тухайн хүн суралцдаггүй) |
| Тэтгэврийн нэрийн дансны лавлагаа | — | ✓ PDF |
| Цэргийн алба хаасан лавлагаа (архив) | — | төлбөртэй, ажлын өдрөөр гардаг → автоматаар авахгүй |

\* Хүүхдийн регистрийн дугаарыг ХУР-ын хүүхдийн мэдээллээс бөглөдөг. Туршсан бүртгэлд хүүхэд бүртгэлгүй байсан тул энэ хэсгийг бодитоор туршаагүй.

## Мэдээллийн эх сурвалж

Эдгээрийг e-Mongolia сайтын JS-ээс олсон. «Миний мэдээлэл» хэсэг ХУР-ын эдгээр сервисийг дууддаг. Жагсаалт нь [extension/sources.js](extension/sources.js)-д байна:

| Мэдээлэл | ХУР сервис | Параметр (`customFields`) |
|---|---|---|
| Эрүүл мэндийн даатгал | `WS300101_getInsuranceFee` | — |
| НДШ | `WS100501_getCitizenSalaryInfo` | `startYear` (өнгөрсөн он), `endYear` (энэ он), `reason` |
| Төлөгдөөгүй нэхэмжлэх | `WS100439_unpaidInvoiceInfo` | — |
| Зээл | `WS100831_citizenLoanInfo` | — |
| Тээврийн хэрэгсэл | `WS100406_getCitizenVehicleList` | — |
| Тээврийн хэрэгслийн торгууль | `WS100403_getVehiclePenaltyList` | машин бүрээр `plateNumber` |
| Тээврийн хэрэгслийн оношилгоо | `WS100409_getVehicleInspectionInfo` | машин бүрээр `cabinNumber` |
| Албан журмын даатгал | `WS100458_MandatoryInsuranceShortList` | — |
| Иргэний үнэмлэх | `WS100101_getCitizenIDCardInfo` | — |
| Гадаад паспорт | `WS100110_passportInfo` | — |
| Үл хөдлөх хөрөнгө | `WS100202_getPropertyList` | — |

Хүсэлтийн хэлбэр нь `POST /api/routes/xyp`:
- header: `X-Auth-Token: <auth-token cookie>`
- body: `{ "target": "xyp-data", "params": { "serviceCode": "...", "sid": null, "customFields": {...} } }`

Сайт өөрөө `customFields`-д `regnum` илгээдэг. Гэхдээ сервер үүнийг token-оос авдаг тул илгээх шаардлагагүй. Хариуны `resultCode: 1` нь «олдсонгүй», өөрөөр хэлбэл мэдээлэл бүртгэлгүй гэсэн утгатай. Параметрүүдийг сайтын `my-info-government/*` хуудасны JS-ээс олсон. 2026-10-07-нд нэвтэрсэн session дээр шалгахад 11 эх сурвалж бүгд амжилттай ажилласан. Харин машин бүрээр дуудах хэсгийг машин бүртгэлгүй бүртгэл дээр бодитоор туршиж чадаагүй.

## Ажиллуулах

**Extension**
1. `chrome://extensions` руу орж Developer mode-ыг асаана. **Load unpacked** дарж `minii-medeelel/extension` хавтсыг сонгоно.
2. e-Mongolia-д ДАН-аар нэвтэрнэ. Extension-ий ногоон дүрс дээр дарж **Шинжлэх** дарна.

**AI: хэрэглэгч key үүсгэхгүй (санал болгох)**

Төслийн эзэн AI сервисийг ([worker/](worker/)) нэг удаа deploy хийнэ. Ингэснээр бүх хэрэглэгч эзний **нэг** key-ээр AI ашиглана.
```bash
cd minii-medeelel/worker
npm install
npx wrangler login                       # Cloudflare бүртгэл (үнэгүй)
npx wrangler secret put GEMINI_API_KEY   # aistudio.google.com-ийн key
npx wrangler deploy                      # → https://minii-medeelel-ai.<нэр>.workers.dev
```
Гарсан URL-ийг [extension/config.js](extension/config.js)-ийн `SERVICE_URL`-д бичээд push хийнэ. Үүний дараа extension суулгасан хүн бүр **тохиргоогүйгээр** «Шинжлэх» товч болон chat-ийг шууд ашиглана.

Байршил: Gemini API зарим бүсэд (жишээ нь Hong Kong) дэмжигддэггүй. Монголоос ирсэн хүсэлт ийм бүсийн Cloudflare серверт ажиллавал «location is not supported» алдаа гардаг. Тиймээс `wrangler.toml`-д `[placement] region = "gcp:us-central1"` тохиргоогоор Worker-ийг АНУ-д ажиллуулдаг.

Тогтвортой байдал: нэг загвар 35 секундэд хариу өгөхгүй, завгүй эсвэл хязгаарт хүрсэн бол дараагийн үнэгүй загвар руу шилжинэ. Загварын жагсаалт нь `worker/src/ai.js`-ийн `GEMINI_MODELS`.

Хамгаалалт: extension-д нууц хадгалах боломжгүй тул сервисийг дараах байдлаар хамгаалдаг:
- IP тус бүрт минутад 10 хүсэлт (хураангуй болон chat нийлээд)
- зөвхөн `chrome-extension://` origin-оос ирсэн хүсэлтэд CORS зөвшөөрнө
- 200KB-аас том өгөгдлийг хүлээн авахгүй
- мэдээллийг хадгалахгүй

**Бусдад тараахаас өмнө:**
- Gemini-ийн үнэгүй хязгаар нэг key-д ногддог тул бүх хэрэглэгч түүнийг хуваалцана. Хэрэглэгч олон болбол «хязгаарт хүрлээ» алдаа гарна.
- Үнэгүй хувилбарт Google мэдээллийг бүтээгдэхүүнээ сайжруулахад ашигладаг. **Бусдын** хувийн мэдээлэл дамжих тул Gemini-ийн төлбөртэй хувилбар руу шилжих хэрэгтэй. Төлбөртэй хувилбарт мэдээллийг ингэж ашигладаггүй.
- Та бусдын хувийн мэдээллийг боловсруулж байгаа тул Хүний хувийн мэдээлэл хамгаалах тухай хуулийн дагуу хэрэглэгчээс зөвшөөрөл авч, нууцлалын бодлого гаргах шаардлагатай.

## Нууцлал

- Өгөгдлийг хэрэглэгчийн компьютер дээр **нууцалсны дараа** хадгална. Хадгалахаас өмнө РД, нэр, хаяг, утас, имэйл, зураг, карт болон дансны дугаарыг хасна.
- AI руу зөвхөн «Шинжлэх» дарах эсвэл асуулт илгээх үед нууцалсан мэдээлэл явна. Юу илгээгдсэнийг side panel-ийн доод хэсэгт байгаа «Дэлгэрэнгүй»-ээс харж болно. Chat-ийн түүх хадгалагдахгүй, side panel-ийг хаахад устна.
- Нууцалсан ч торгуулийн дүн, даатгалын төлөв, зээлийн үлдэгдэл мэт **хувийн санхүүгийн мэдээлэл AI руу очно**. Бүтээгдэхүүн болгохдоо хэрэглэгчээс тодорхой зөвшөөрөл авах хэрэгтэй.
- ХУР-ын сервис бүрийг дуудах үйлдэл иргэний «мэдээлэл хандалтын түүх»-д бүртгэгдэж болно. Иргэн өөрөө өөрийн мэдээлэлд хандаж байгаа тул энэ нь хэвийн.
